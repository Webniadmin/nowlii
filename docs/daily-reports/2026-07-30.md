# 2026-07-30 — production hardening, scheduled calls, and three things that were only artwork

11 commits, all on `feat/realtime-voice-call` (pushed). Backend and `nowli-ai` both deployed
to EC2. The theme of the day: several features that looked finished turned out to do nothing
at all when opened up.

---

## Shipped

### Production hardening (`cb9d1ac`)
- **`nowli-ai` was an open door to the OpenAI bill.** `/api/v1/` took no credentials, and
  `/realtime/token` mints Realtime keys while three other routes run paid models — anyone
  who knew the IP could spend money. Not hypothetical after the 07-23 key leak. It now
  verifies the caller's Django access token locally (same HS256 secret, no network hop, no
  second credential to embed in the APK).
- **The companion catalogue was anonymously writable.** `NowliiPredefinedOptionViewSet` was
  `AllowAny` on a full `ModelViewSet`, so any anonymous caller could rename or **DELETE**
  every avatar. Now read-public / write-admin.
- `SECRET_KEY` is enforced in production (the app refuses to boot on a weak one), DRF now
  fails closed, HTTPS switches added as env flags (all off — prod is still plain HTTP), full
  JWTs no longer printed to logcat, Android release signing wired, `.env.example` for both
  services.

### AI call: time awareness + wakelock (`ffd380c`)
The extension card used to appear silently at 60 s left. Nowlii now says it out loud 10 s
before, and is kept genuinely time-aware (a silent context item per minute). The wakelock
existed but was set once in `initState` and never checked — `FLAG_KEEP_SCREEN_ON` belongs to
the window and was lost every time the app left the foreground. Now re-asserted on resume
and verified.

### Scheduled AI calls (`c5c55f5`, `bab7508`, `b3b0f27`)
"Enable call" on a quest now schedules the call and fires a local notification 5 minutes
before. The hard part was the **daily limit of 2, which is never reserved** — a scheduled
call is a plan, not a booking. So the app warns *before* a swipe spends the last call and
offers "Move to tomorrow" *after*.

Two follow-ups found by reading the code back:
- the notification never said *when* the call was, and
- a call scheduled closer than the lead time got **no reminder at all** (17:58 for 18:00).

And one real bug found by testing minute precision: `post_save` sees the in-memory value, so
a caller assigning `select_a_time='16:30'` handed the signal a `str` — which raised inside
`post_save` and **took the whole quest save down with it**. Now coerced, and the receiver
never propagates: a quest is the user's work, a reminder is a convenience attached to it.

### Account deletion + privacy policy (`756d776`)
`Delete My Account` opened a dialog and then called a handler whose entire body was a
SnackBar reading "Account deletion initiated". No request, no endpoint, nothing removed —
a hard rejection under Play's data-deletion policy and Apple 5.1.1(v), and a false statement
under the GDPR. Now a real hard delete (cascade + the S3 avatar, which does not cascade).
Privacy Policy links to https://www.nowlii.com/privacy-policy from both places; Terms of
Service does not exist yet, so both references are commented out with `TODO(legal)`.

### Sessions that survive (`69101d3`, `e049aed`, `9f0ca6c`, `260d3ff`)
The app had stored a refresh token since day one and **no refresh route was ever registered**
to spend it. Four rounds, each fixing a gap the previous one left:

1. Added the route + `lib/api/session.dart` (proactive refresh from the token's own `exp`,
   single-flight because rotation blacklists the old token).
2. **The config defeated it:** both lifetimes were 31 days, so both expired together and
   users were signed out on day 31 anyway. Now 60 min / 90 days, with a boot guard and a
   test — nothing else notices until day 31.
3. **Expiry checks are not enough:** a token rejected after a key rotation is *not* expired,
   so nothing triggered a refresh. A 401 now routes through `reportUnauthorized()`.
4. **The route guard accepted any non-empty string** as a session. Now it reads the tokens'
   expiry locally and refuses a dead session before letting anyone in.

## The device report, and what it actually was

Reported: Insights "Unable to load insights", Progress empty, quest creation failing, wrong
image on Home. It read like the APK had lost the backend.

It had not. Verified against live prod with a fresh token — quests 200, insights 200,
subscriptions 200, quota 200, **quest create 201** — and the same endpoints with a token
signed by the previous key: **401 across the board**.

One cause, four symptoms: the `SECRET_KEY` rotation earlier that day invalidated every
issued token, and the app had no way back from a 401. The "wrong image" was the same bug —
that slot is the companion avatar from the profile, and the profile fetch was 401ing, so it
fell back to the generic placeholder.

**Lesson for next time: after rotating `SECRET_KEY`, say "sign out and back in" in the same
breath.** It was mentioned that all users would be logged out, but not that a build without
401 recovery would sit there failing silently instead of asking them to.

## Verified

81+ backend tests (27 new in `voice_calls`, which had none; users grew from 0 to 25) and 49
Flutter tests, all passing. `flutter analyze` 0 errors. Debug APK builds. On prod: the deploy
proven by 404→401 on a new route, and the two secrets proven to match by minting a real
Django token inside the backend container and having `nowli-ai` accept it (200) while
rejecting a tampered copy (401).

## Not verified

only be proven there — lock screen, cold start, reboot, exact-alarm denied.
