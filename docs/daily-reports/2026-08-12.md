# 2026-08-12 — The companion poses land, and the mapping under them turns out to be wrong

**Branch:** `feat/design-implementation`. Frontend and docs only — **no backend or `nowli-ai`
code changed**, and production was verified byte-identical to committed `HEAD`, so the only
AWS action all day was the QA allowlist (restored for testing, emptied again at the end).

The day started as "import the pose art design delivered". It turned into four other things,
one of which would have shipped a visible bug to every user who is not the QA account.

---

## 1. Six characters × four poses

Design delivered the art, so the P4 item that had been "code done, waiting on art" since
08-11 is closed. 24 PNGs now live in `assets/companions/` as
`<option id>_<pose>.png` — sleeping, reading, speaking, waving — transparent, 512px,
4.5 MB total, imported from Figma `y4Wzcc018iQEfEjm8T0Yjd` node `36:8041`.

`NowliiAvatar` takes a `pose:`. **Poses are bundled-only and never come from the network:**
the backend stores one neutral picture per companion, so asking S3 for a sleeping one
returns the standing one and the slot goes quietly back to being wrong. `pose` defaults to
`.neutral`, which *is* the profile URL — the pre-pose behaviour, still right for the profile
tile and the pickers.

Twelve of the seventeen call sites now name a pose. None of them was guessed: `git diff`
showed which asset each one had replaced, and the old filename says the pose —
`companionSleeping` on the two out-of-sparks slots, `homeQuestBlob` (the one holding a book)
on the home quest card, `Popup_Speaking` / `callStarted` / `popUpSpekingTwoCarton` on the
nine speaking slots.

**Two traps in the Figma file**, worth knowing before the next art drop, because column
position is *not* the pose:

- **Character 3** authors sleeping and speaking in the opposite columns to the other five.
- **Character 5's** sleeping frame also contains a second, awake copy; picking by size or
  order takes the wrong one.

Both were caught by rendering every candidate and looking, not by trusting the layout.

`waving` shipped but no slot claims it yet.

## 2. The mapping under the avatars was wrong for five of the six companions

This is the find of the day, and it was luck that exposed it: a debug line in the call log
read `predefined_option: 12`.

The art was chosen by `(optionId - 1) % 6`. Production serves ids **2, 3, 4, 6, 10, 12** —
the table has been reseeded and the rows are neither 1-based nor contiguous. So:

| companion | id | resolved to | should be |
|---|---|---|---|
| Milo | 2 | orange | white |
| Knotty | 3 | green | purple |
| Gumo | 4 | purple | green |
| Fizzy | 6 | blue | small orange |
| Bloop | 10 | purple | orange |
| Zee | 12 | blue ✓ | blue |

Five of six wrong, and ids 4/10 and 6/12 collapsed onto one slot each. It had hidden for
months because it only ever fed the **offline fallback tile** — and because the QA account
is Zee, the single id the arithmetic gets right, so every check anyone had run agreed with
it.

Poses read this on **every draw**, so it was about to become visible: a Milo user would have
met the white ghost on the hero card and an orange character reading on the quest card, on
the same screen.

Now resolved from the `avatar_logo` filename (`…/nowlii_logos/zee.png` → `zee`), then the
preset `nowlii_name`, then the old id arithmetic as a last resort. **Deliberately not the
displayed name** — the user is invited to rename their companion, and picking the character
by that name is a bug this app already shipped once, on 08-04.

`test/companion_pose_test.dart` now asserts the mapping against the real production ids and
URLs, so any return to an id-keyed lookup fails the suite. The real fix is a stable `slug`
on `NowliiPredefinedOption`; recorded in `future-checklist.md` P4, and **until then the S3
filenames must not be renamed**.

## 3. The whole call screen appeared to pulse — and my first fix was a redesign

Reported as "the whole app pulses when a call starts". Cause was the 08-11 avatar swap:
`callStarted.png` is the **entire composition** — character, disc and two halo rings — in a
single 1320px image drawn into a 240 box, so its solid disc landed at 134dp on screen.
`popupSpeking.png` is **only the disc**, and at 240 it rendered 177dp while leaving the
182→240 band empty, exposing the faint pulsing gradients and the inner glow that the artwork
used to cover. The breathing mass looked far bigger than before.

My first attempt made every ring proportional to screen width. That was **re-designing a
thing I had broken instead of restoring it**, the user said so plainly, and it was reverted.

The fix that shipped: the original widget restored verbatim — every ring number, the 240
box, `BoxFit.cover`, the 1.05 scale — with only the picture changed. New asset
`assets/svg_images/callStartedEmpty.png` is `callStarted.png` with the orange character
lifted out and the disc beneath rebuilt from `popupSpeking` at matching scale (its 180px
core scaled to the original's 728px), so canvas, halos, disc and position are identical. The
companion sits inside at 87 — the height the baked-in character measured in that box —
within the same `Transform.scale`, so it breathes with the disc exactly as it always did.

`git diff` on that method is now three things: the asset, the child, and an import.

A first attempt at removing the character by radial reconstruction failed and is worth not
repeating: the character covers the disc's centre, so there are no unmasked samples at small
radii and the middle stayed as it was. Compositing the real disc from the other asset is
both simpler and exact.

Measured after the restore: the composition spans 70–76% of the width at 411dp, with margin.
At 320dp the rings still reach the screen edges — they did originally too (320 + 40 = 360),
so that is design, not regression.

## 4. The mood face on the summary, and a trap in `dominant_emotion`

"Mood detected" was a fixed `Icons.mood`, so a call that ended in tears and one that ended
laughing carried the same smile. Nine faces imported from Figma `40:8478` as **SVG** —
`flutter_svg` was already a dependency, and the PNG exports carried a baked `#DFEFFF`
background from the popup behind them. `lib/utils/mood_icons.dart` maps to them.

**The first version was wrong, and only running it showed why.** I gave the
`dominant_emotion` category precedence over the free-text sentence, reasoning that a
classification beats prose. But `nowli-ai` reports `happy: 100.0` whenever it has no emotion
scores at all — which is exactly what a silent emulator call produces — so the summary read
"You sounded pretty neutral throughout our chat" under a beaming yellow grin. The sentence is
what the model actually wrote about *this* call; the bucket is a backstop. Flipped, and the
same call now shows the calm green face.

When neither input says anything recognisable the lookup returns null and the card keeps its
neutral glyph. Inventing a cheerful face for a call the model could not read is the one
answer that is worse than no answer.

## 5. "Nothing to save yet" over a summary that was saved

The summary is persisted automatically as soon as it loads. The "Save reflection" button only
ever handled the optional personal note, so with the note box empty it answered "Nothing to
save yet" — while the summary had already been saved and duly appeared in Call History. The
button was contradicting the app.

Three honest outcomes now: the note was saved, or there was no note but the summary is
stored anyway, or genuinely nothing was kept. Verified on device: green "Summary saved to
your history." after a call that produced one, and the orange "Nothing to save yet" only
after a call that produced nothing.

## 6. A 320dp sweep, and what it found

Home, Quests, Progress (both scroll positions), Insights, Profile, Edit Profile and the
rename screen, all driven to **exactly 320.0dp** (`wm size 840x1867` at density 420; the
arithmetic is 840 ÷ 2.625) against the live backend. **Zero `RenderFlex` overflows** in the
whole session — checked in the log, not judged by eye.

Three real defects, all pre-existing:

- **Edit Profile** carried a hardcoded `\n` from Figma in "Pick a new form or ↵ customize
  your current one" with `maxLines: 2`. At 320dp the first half alone used both lines and
  the second half vanished silently. Wraps naturally at `maxLines: 4` now, and the card is
  `minHeight` rather than a fixed 140 — at 411dp with the OS font slider at its 1.15 cap,
  four lines exceed 140 by about a point.
- **The paywall timeline** — the Spark / Rhythm / Independence / Release / Graduated block —
  had a fixed row height of 60 and nothing flexible inside a `spaceBetween` row, so at 320dp
  there was nothing to give. 60 is a floor now, the stage column is `Expanded`, card padding
  drops 24 → 16 and the type a point below 360dp.
- **The trial CTA** read "Continue — 1 day…". It scales down instead of ellipsising now,
  matching what `custom_button.dart` already does.

## 7. Two more, reported late

- **The receipt footer** drew `receipt_fizzy.png` next to "Not a diagnosis. Just a mirror."
  That file is byte-identical to the Figma export of fizzy standing neutral, so every
  receipt showed the same orange character whoever was reading it. It is the companion now,
  at the same 32 × 48 footprint — which needed an optional `height` on `NowliiAvatar`, since
  every other slot it serves is square.
- **The profile name** used the shared 52pt display title in a pill with 225dp of usable
  width; an eight-character name needs about 250dp, so it ran edge to edge. 40pt with a
  scale-down locally — the style is shared with the quest screens and they are unaffected.
