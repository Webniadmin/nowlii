Five commits. The day's work carried the updated design past onboarding and into the three
screens that follow it: the home screen, the receipt a call leaves behind, and the paywall.

Two things are worth knowing before reading the rest.

**Nothing was deployed and nothing reached a phone.** The device test that has been the

**The work sat uncommitted until 2026-08-03.** Five days of features were on disk only, with

committed now, in the five commits below, verified before each one.

## Shipped

### A question worth asking, and a note that survives (`de99cf9`)

The receipt gains its last two fields.

`tiny_question` — one short question the user could ask themselves — is written by the same
GPT pass that already produces the summary sentences, so it costs nothing extra. nowli-ai
sanitises it and caps its length before it reaches anyone. An empty value is a valid answer
and the card hides: better than a question the model reached for because a field asked to be
filled.

`note` is the one field on a receipt the user writes themselves, and it has its own PATCH
endpoint for a specific reason. The app re-posts the generated summary every time the summary
screen is shown; sharing an endpoint would have meant a re-post silently carrying the user's
own words away. A test pins exactly that, alongside cross-user 404s and the distinction
between an absent `note` field (400) and an empty one (deliberately means *delete it*).

**Two date bugs fixed here, both invisible until they weren't.** The project-wide DRF
`DATETIME_FORMAT` is `"%d-%m-%Y %H:%M:%S"` — neither parseable by the client nor
offset-bearing. Every receipt date arrived as `null` and the dates simply vanished from the
screen. Worse, `ScheduledCall.scheduled_for` is UTC and was being read as local time, which
put **every call reminder out by the device's offset** — a reminder feature that has never
been tested on a device would have failed there for a reason nobody would have guessed.
Both serializers now say `iso-8601` explicitly.

Migrations `voice_calls.0007` (note) and `0008` (tiny_question).

### Images that never loaded, and a skip that led nowhere (`9cc4342`)

Four screens pointed at an asset whose filename contains a `?`. Windows cannot put that
character in a filename, so the file does not exist in this repo at all and those screens
rendered a broken image on every platform. Two more pointed at asset getters that no longer
exist under those names.

The voice check's close button called a bare `Navigator.pop`. It is the last onboarding
screen and it is reached with `go`, so there was nothing underneath it: the pop took the only
page off the stack, go_router asserted, and the user sat on a black screen with no way out.
Skipping now lands where finishing lands. This was one tap away from the redesigned
onboarding flow that shipped the day before.

### The day's two calls, named (`b637a6a`)

The home screen is rebuilt to the updated design, and the daily AI-call allowance now uses
the product's own word: **sparks**. The call screen counts "Spark 1 of 2", the home card
closes the day out once both are spent, and the swipe button stops inviting a call it cannot
start.

The counting lives in one type (`SparkState`) because three screens read it and they must not
drift apart. Two edges are why it is a type and not a pair of ints:

- **Unlimited QA accounts** (`VOICE_CALL_UNLIMITED_USERS`) come back as `limit: -1`. Rendered
  naively that reads "Spark 1 of -1", and every "you're out of sparks" branch is wrong for
  them — which is exactly the account the testing would have been done from.
- **An unknown quota must never look like an empty one.** A failed fetch says nothing and
  keeps the normal button; the backend gates the call regardless and is the real authority.

"Limited by design" no longer writes "two" into its copy — the limit is an env var the
backend owns, so the screen asks.

### A library of receipts, and one you can keep (`85b5e9f`)

Every call already produced a receipt; it existed for as long as the summary screen was on
screen and then it was gone. There is now a numbered library of them and a detail screen that
shows the call back with the question it raised, plus the note the user can write and edit.

"Keep this receipt" renders to PDF and hands it to the system share sheet. Sharing rather
than writing to Downloads keeps this clear of Android's storage permissions, which behave
differently on every OS version. New dependencies: `pdf`, `printing`.

Dates now come back through one parser (`api_date.dart`) instead of being parsed at each call
site — the backend sends UTC, the screens show local, and that is invisible until someone is
in the wrong timezone.

The library's "See what keeps coming back" scrolls Insights to the section that already
aggregates those repeated words, rather than building a second answer to the same question.
The old call-history screen it replaces moved to `lib/experimental/` per the standing rule.

### What you will pay, and when it changes (`46610a5`)

The Pro screen and the trial popup are rebuilt to the updated design. Behind the artwork, the
decreasing price is now shown as **dated rows** — "Rhythm from 3 Sep, Independence from 3
Dec" — rather than month ranges. The backend describes the plan as `from_month` / `to_month`,
which is the right shape to bill from and the wrong shape to show a person; what they want to
know is what they will pay and when it changes.

Dates anchor to `started_at` for a subscriber and to today for someone still deciding, where
they read as an honest "if you subscribe now". Month arithmetic clamps to the last valid day:
`DateTime(y, m + n, d)` rolls overflow forward, so someone who subscribed on the 31st would
have been shown price changes in the wrong month entirely.

"Seven days. On us." moved to the end of sign-up, where the trial is already running, and is
claimed through a gate so it appears once and only once. The splash keeps the same check as a
fallback for anyone who quits before reaching it.
