# 2026-07-31 — HTTPS goes live, and the onboarding redesign lands

Seven commits. `main` was merged and now matches production; onboarding work continues on
**`feat/design-implementation`**. Two themes: the release blocker that had stood for weeks
came down, and a redesign turned up a run of features that looked finished but did nothing.

**Nothing was tested on a device today.** That is the single biggest gap going into tomorrow.

---

## Shipped

### HTTPS on a real domain (`0380a4f`)

The blocker was never a build-config problem — it was the plain-HTTP backend. Android has
blocked cleartext since API 28, so a release APK pointed at `http://16.170.191.239:8000`
failed *every* request. That is gone:

- `https://api.nowlii.com` → nginx → `:8000` (Django), `https://ai.nowlii.com` → `:8001`
- One Let's Encrypt cert covering both names, expires **2026-10-29**, `certbot.timer` renews
- `ufw` confirmed inactive — the AWS security group is genuinely the only firewall

Two config details are load-bearing rather than cosmetic. The `ai` vhost disables proxy
buffering, because `/api/v1/chat-stream` is SSE and nginx would otherwise withhold the whole
stream until the response ended. And the Apple domain-association location is an **exact**
match so it cannot shadow `/.well-known/acme-challenge/` and quietly break renewal two months
from now — both paths were probed.

**Verified, not assumed:** valid cert from outside; `/api/docs/` and `/admin/login/` 200;
protected routes 401 without a token and **200 with one** (quests, profiles, rest-days, quota,
subscriptions, scheduled); `nowli-ai` accepting a **Django** token over HTTPS and rejecting the
same token with one character changed; `session/new` → `realtime/token` returning 200 with
`gpt-realtime-mini` and `voice: marin`, so the cost cap and gender selection both survived.

`nginx` config is now checked into `deploy/nginx/` — it existed in exactly one place, on the
box, and `git archive` ships only `nowli-backend/` and `nowli-ai/`.

### Apple sign-in can now reach the app on Android (`9e6fee3`, deployed)

`apple_web_redirect` answered Apple's `form_post` with a 307 into the plugin's `intent://`
scheme. Chrome refuses to follow a server-driven `intent://` that no user gesture asked for,
so the Custom Tab sat on a blank page and `POST /api/auth/apple/` never fired — the login
looked like it worked right up until nothing happened. It now serves a page that attempts the
hop *and* offers a button, because the gesture is the part Chrome actually wants.

Apple's parameters arrive in a POST body, so they are attacker-influenced: HTML-escaped in the
`href`, JSON-quoted in the JS. 6 tests, including that a `"><script>` parameter comes back
with zero raw script tags.

### Social login on the new domain

- **Google needed no changes at all** — checked rather than assumed, because "we changed the
  backend URL" sounds like it should matter. The native flow matches on package + SHA-1 and
  never sees the backend URL. Client ids match between prod and the app (a mismatch there is
  the classic silent failure: every login 401s and nothing says why).
- **Found: prod had no `APPLE_CLIENT_IDS` at all.** It lived only in the local `.env` and was
  never copied to the box, so Apple login was **503 in production** regardless of the URL.
  Now set; the endpoint verifies (401 on a bad token).
- **Apple portal config verified by asking Apple**, with control probes so the result means
  something: the real Services ID + Return URL is accepted, while a wrong path, a wrong host,
  the **old tunnel URL** and a bogus Services ID are all rejected.
- **Found: allauth was generating `http://` redirect URIs** behind nginx — Django had no idea
  it was behind TLS. Fixed with `BEHIND_TLS_PROXY=True`, which only sets
  `SECURE_PROXY_SSL_HEADER` and redirects nothing, so it was safe with `:8000` still open.

### Onboarding redesign, phases 1–4 (`14119e9`, `8bd830d`, `3c8698e`, `efbd1ba`)

Read the updated Figma flow (33 screen frames) against the built flow and implemented it in
four reviewable phases.

**Phase 1 — existing screens.** The name field had *no validation*: an empty name went
through and was posted to the profile. Now min 1 / max 30, letters-spaces-hyphens, with a
unicode-aware filter rather than `A-Za-z` (the app ships Español; an ASCII filter eats half of
"José"). Companion-name errors at 2/12 — and the field no longer sets `maxLength`, because a
hard cap swallows the 13th keystroke and the over-length error could never have appeared.

Two behaviours were wrong rather than missing: the **↻ control advanced the avatar index**,
silently swapping the companion chosen one screen earlier on a screen whose only job is naming
it; and the parent guessed whether a name was custom by testing it against a hardcoded list
(`['KNOTTY','BLOOBY',…]`) that never matched the real companions, so **every suggested name was
filed as a custom one**.

**Phase 2 — the two new steps.** "Limited by design" (7/8) and the receipt preview (8/8),
folded into the numbered flow, so the step count moved 6 → 8 through the single constant phase
1 introduced. Trial popup rewritten dark, logic untouched; CTA fixed to the bottom because on a
small screen the content pushed it below the fold; price now read from the plan's first phase
instead of a hardcoded string. Dropped the month-by-month billing breakdown per the design
notes (it still lives on the paywall). Fixed copy promising "30 days of full access" when the
trial is seven.

**Phase 3 — hygiene.** The worst find of the day: **`isFirstTime` was cleared unconditionally**,
including when profile creation failed or the data was incomplete. That marked the user as done
with onboarding while leaving them without a profile, and nothing ever sent them back — a
permanent dead end reachable by simply skipping the name step. Onboarding answers were also
memory-only, so killing the app halfway threw everything away; they now persist and restore.
Two screens greeted people by the name from the mock ("YOU'RE ALL SET, JULIE!" — moments after
they typed their own). Navigation used `push` for back *and* skip, growing the stack instead of
moving through it.

**Phase 4 — the voice check, and words.** The voice check was theatre: ten seconds of
countdown with the microphone never opened and nothing sent anywhere, so a denied permission
surfaced during the user's first real call instead of on the screen built to catch it. It now
listens, drives the waveform from live input level, and sends what it heard for emotion
detection — on `speech_to_text`, already a dependency, so no new native package. "Words you
circled around" rides along in the GPT pass that already runs at call end (no extra cost),
sanitised independently by both services, stored on `CallSummary` (migration `0006`), and shown
after a call. The section hides when empty rather than inventing something.

## Still open

- **Nothing has been tested on a device.** Everything above is verified by tests and by
  probing the servers; none of it has been seen on real hardware.
- **Phase 4 is not deployed.** It touches the backend (migration `0006`) and `nowli-ai`
  (prompt). Phases 1–3 are frontend-only and ship with the APK.
- **No APK built** — deliberately, at the user's request, since the design work was mid-flight.
- **Cutover not done**: `:8000`/`:8001` still open, `SECURE_SSL_REDIRECT` still off, no nginx
  HTTP→HTTPS redirect. All three would break any pre-HTTPS build the moment they land.
- **Companion name suggestions are placeholder copy** (`companion_name_suggestions.dart`). The
  design asks for "5–7 predefined names per archetype" without saying what they are, and the
  backend has no field for them.
- **Figma hit its tool-call limit** partway through. "Limited by design" was built against a
  real screenshot; **"Tonight's receipt" layout is an estimate from its text content**, and six
  frames in the Welcome Activation Flow were never seen at all (their copy is known only from
  the dev notes).
- **Voice check sends the transcript, not raw audio**, so Hume prosody is skipped and only text
  emotion runs. Adding it needs a recorder package.
- Apple may ask for a domain-verification file; nginx is already wired to serve it.
